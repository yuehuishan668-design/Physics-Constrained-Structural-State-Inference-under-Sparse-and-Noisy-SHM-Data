# Data dictionary

Large numerical arrays are excluded from Git. This document records their roles and the tracked evidence that audits them.

## Raw simulation output

The 3000-case raw NPZ is generated by `src.data_generation.generate_dataset` through `scripts/run_q2_generate_debug_plus_3000.sh`.

| Field | Meaning | Expected shape / type |
|---|---|---|
| `X_abs_accel` | Noisy approximate absolute floor acceleration | `(3000, 2000, 4)` |
| `X_clean_abs_accel` | Clean approximate absolute floor acceleration | `(3000, 2000, 4)` |
| `y_damage` | Storey stiffness-loss ratios ordered floors 1–4 | `(3000, 4)` |
| `story_drift` | Interstorey drift histories | `(3000, 2000, 4)` |
| `ground_accel` | Base-input acceleration histories | `(3000, 2000)` |
| `amplitude_g` | Parametric excitation amplitude | `(3000,)` |
| `frequency_hz` | Parametric excitation frequency | `(3000,)` |
| `noise_level` | Case-wise response-noise level | `(3000,)` |
| `case_id` | Stable case identifier | `(3000,)` |
| `dt` | Time step | scalar, 0.01 s |

The excitation is a controlled parametric excitation ensemble, not a set of recorded earthquake ground motions.

## Target tensor

`y_damage[:, 0:4]` corresponds to storeys 1–4. A nonzero entry is the prescribed column stiffness-loss ratio for that storey. It is not a label for cracking, yielding, deterioration, or collapse.

Dataset composition:

- 3000 successful cases;
- 596 healthy;
- 1208 one-storey-damage;
- 1196 two-storey-damage.

## Split identities

Repeated P1/P2 split files contain:

| Field | Meaning | Expected length |
|---|---|---:|
| `train_idx` | Training case indices | 2100 |
| `val_idx` | Validation case indices | 450 |
| `test_idx` | Test case indices | 450 |

Seeds 0–9 define the repeated partitions. P3–P5 use one clean fixed split and must not be pooled with P1/P2.

## Descriptor matrices

Canonical descriptor NPZ files contain train/validation/test feature matrices and labels:

- `F_train`, `F_val`, `F_test`: standardized descriptors;
- `F_train_raw`, `F_val_raw`, `F_test_raw`: unstandardized descriptors;
- `y_train`, `y_val`, `y_test`: storey-level targets;
- case IDs and split indices where recorded.

Expected feature dimensions:

| Representation | Dimension | Provenance |
|---|---:|---|
| 92D | 92 | 59 structural-response + 19 base-input-dependent + 8 exact-generator-frequency-derived + 6 generator metadata; privileged reference |
| 86D legacy | 86 | removes metadata but retains exact-frequency-derived information; not deployment-clean |
| 78D | 78 | signal-derived, assumes measured base-input history; primary representation |
| 59D | 59 | structural-response only |

Feature names and provenance are tracked in `configs/sss_fast_revision/descriptor_set_manifest.csv`, `configs/sss_fast_revision/descriptor_set_summary.json`, and the manuscript source-data tables.

## Matched-noise fields

P3 descriptor files preserve the same clean targets and case identities across 0/5/10/20% structural-response noise conditions. The base-input history remains clean. Nonzero levels contain five deterministic realizations. Noise perturbs the structural responses; it does not redefine the target or descriptor provenance.

## Sensor dependency fields

The dependency manifest created by `build_exhaustive_sensor_layout_descriptor_datasets.py` includes:

- `feature_index_78d`;
- `feature_name`;
- `required_structural_sensors`;
- `required_sensor_count`;
- `requires_story_1` through `requires_story_4`.

A descriptor is retained only if its full dependency set is present. Missing sensors are not zero-masked and descriptors are not redesigned.

## Prediction and bootstrap arrays

The untracked P4 prediction archive records:

- `prediction`: layout × test case × storey predictions;
- `layout_tag`: layout identity;
- `y_test`: shared targets;
- `test_case_id`: shared case IDs.

P5 resamples complete test cases, retains all four storey outputs together, and applies the same resampled indices to every compared layout. Tracked edge summaries include point changes, relative changes, percentile intervals, and beneficial-direction flags.

## Tracked processed manuscript evidence

Small evidence files required by the quick verifier remain in Git:

- factorial means/effects;
- calibration paired statistics;
- matched-noise summaries and bias/clipping diagnostics;
- 15-layout result table;
- 28-edge bootstrap summary;
- figure-source CSVs and final manuscript tables.

These files support fast audit. They are not substitutes for the omitted raw response arrays when performing a full rerun.
